# VoxelBench Phase 0–1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Sinter CT Annotator (version 10) into VoxelBench: a public repository whose one page runs as a static site or as a claude.ai artifact, with nothing tied to Sample 2, and with support for scans over 2 GB.

**Architecture:** Copy the version 10 code into a new repository and keep its module layout (`ct_*.js`, pure logic tested with `node --test`). One storage interface picks its back end at runtime: the artifact database when `claude.use('db')` answers, otherwise a project file. Large scans load as a block-mean binned volume that the rest of the code treats as a scan with larger voxels.

**Tech Stack:** Plain browser JavaScript (no bundler), three.js r128, jsPDF 2.5.1 from cdnjs, Node 23 `node:test`, GitHub Pages, GitHub Actions. Python 3.12 (the lab's analysis environment) only to capture reference fixtures.

**Spec:** `docs/DESIGN.md`. Phases 2–6 get their own plans.

## Global Constraints

- Scan data are read-only. Never write into the lab scan folders.
- Public repository: no CT data, no lab sample table, no saved runs, no private notes, no absolute paths into the lab's file share, no user names. Never open or copy locked prediction files.
- Local repository path: `~/code/put_github_repos_here/voxelbench`, outside Dropbox. Copy the code in; never move a folder out of Dropbox.
- Local-only test inputs live in a local folder outside the repository, reached through the environment variable `VOXELBENCH_LOCAL_DIR`. Tests that need them skip when it is unset.
- Creating the GitHub repository, every push, and every artifact publish need Matt's explicit go-ahead at that moment.
- Version 10 (the lab's existing annotator artifact) stays untouched. VoxelBench's artifact build is a new artifact.
- Red-green TDD for testable logic. Visual changes are verified by rendering and screenshots that Matt reviews.
- American English. Technical wording only (approved terms: porosity; pores AR ≤ 2.5 / AR > 2.5; pores at FOV edge; low-density regions; high-gray / low-gray / baseline zones; gray offset; ESD; pore threshold). Expand acronyms on first use in UI text.
- No number is shown without its provenance. Absent or failed values never display as zero or healthy.
- Conventional Commits, with commit messages ending in `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A scan folder with one slice of a different size or bit depth** (a stray preview TIFF): the load stops and names the file. Pinned in Task 6.
2. **A project file from a newer schema version, or one that isn't a VoxelBench project:** import refuses with a message and changes nothing. Pinned in Task 2.
3. **Free memory just under the budget** (a scan a few percent over 1.2 GB): the next binning factor is chosen, and the page states it before loading, not after a crash. Pinned in Task 6.
4. **A region label renamed or deleted after regions use it:** existing regions keep their label id and show the label as "(deleted label)", never crash the draw loop. Pinned in Task 4.
5. **The static build with no download capability** (Safari, a plain file:// open): every save falls back to an `<a download>` link and says where the file went. Pinned in Task 2.

### Task 6: Large scans: budgeted binned loading

**Files:**
- Create: `app/vb_volume.js`, `app/version.js` (`window.VB_VERSION = '0.1.0'`, loaded first in `index.html`), `tests/volume.test.js`, `tests/fixtures/block_mean_reference.json`
- Modify: `app/ct_app.js:127-185` (load path), `app/ct_views.js:170-185` (full-resolution XY), `app/index.html`

**Interfaces:**
- Produces (`window.VBVolume`):
  - `MEMORY_BUDGET = {default: 1.2e9, safari: 0.6e9}` (bytes for the stored 16-bit volume)
  - `budgetBytes(userAgent, search) -> number`: `?budget=<GB>` overrides; Safari is detected by a UA with `Safari/` and no `Chrome/`
  - `planBinning({width, height, depth}, budget) -> 1 | 2 | 3 | 4`: the smallest f with `floor(w/f)·floor(h/f)·floor(d/f)·2 ≤ budget`; throws `Error('Too large even at 4× binning')` beyond that
  - `binGroup(slices: Uint16Array[], width, height, f) -> Uint16Array`: block mean over f×f×f, trailing voxels dropped, rounded to nearest, matching `ctio._block_mean`
- App state gains `state.binFactor` and `state.nativeVoxelMm`. `state.voxelMm = nativeVoxelMm · binFactor`. `state.dims` are the binned dims.
- `CT.provenanceLine({voxelMm, binFactor, calibrated, toolVersion}) -> string`, for example `Computed at 80 µm voxels (2× binned from 40 µm); smallest resolved pore ESD 0.24 mm; gray uncalibrated; VoxelBench 0.1.0`. The smallest resolved ESD is 3 voxels. Shown under the porosity summary, in the sheet's scan line and in every CSV header.
